## andrej-karpathy-skills

[forrestchang/andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)는 Andrej Karpathy가 X(트위터)에 올린 LLM 코딩 pitfall 관찰을 바탕으로 만든 `CLAUDE.md` 파일이다. Karpathy는 OpenAI 공동창업자이자 전 Tesla AI 총괄로, 딥러닝 교육 콘텐츠로도 유명한 AI 연구자다.

Karpathy가 지적한 문제들은 아래와 같다.
- 모델이 가정을 확인 없이 그냥 진행함
- 혼란스러워도 멈추지 않고, 명확히 해달라고 하지 않음
- 코드를 불필요하게 복잡하게 만들고 추상화를 남발함
- 요청과 무관한 코드/주석을 건드리는 부작용

이 문제를 4가지 원칙으로 정리했다:

| 원칙                        | 핵심                                     |
| ------------------------- | -------------------------------------- |
| **Think Before Coding**   | 가정은 명시적으로, 혼란스러우면 먼저 질문, 여러 해석이 있으면 제시 |
| **Simplicity First**      | 요청한 것만. 투기성 기능, 불필요한 추상화·유연성·에러 처리 금지  |
| **Surgical Changes**      | 요청과 직접 관련된 코드만 수정, 인접 코드 "개선" 금지       |
| **Goal-Driven Execution** | 성공 기준을 먼저 정의하고, 검증될 때까지 루프             |

설치는 Claude Code 플러그인으로 바로 적용하거나, `CLAUDE.md`에 내용을 추가하는 방식 두 가지를 지원한다. 나는 전자를 택했다.

## 효과있을까?

트리거 조건(코드 작성, 리뷰, 리팩터링)이 맞으면 자동 호출될텐데, 아직 코드 작업이 없어서 후기랄게 없기는 하다. 요새 플랜 모드(plan mode)의 중요성을 깨닫고 굉장히 세세하게 작업 지시를 내리기 때문에, 필요성이 높아보이진 않는다. 사이드 프로젝트를 실행해서 좀 덜 구체적인 명령으로 코드를 짜거나 할 때 확실히 효과를 체감할 수 있을 것 같다.
