## 선제적 압축

```
대화가 길어지면, 다음 에이전트를 위해 HANDOFF.md 파일을 작성하도록 지시하고 /clear 로 새롭게 시작하세요.

ykdojo의 실제 프롬프트:

"Put the rest of the plan in the system-prompt-extraction folder as HANDOFF.md.  
Explain what you have tried, what worked, what didn't work,  
so that the next agent with fresh context is able to just load that file and nothing else to get started on this task and finish it up."
```

`/compact` 가 같은 역할을 하지만 handoff.md 파일에 더 구조적인 지시를 남기는 것으로 이해했다. 컨텍스트가 일정 수준을 넘어가면 클로드가 알아서 컨텍스트를 압축하는데 그 것과 얼마나 다를지 궁금하다.

## 단축어

```bash
alias cc='claude'
alias ccc='claude --continue'
alias ccr='claude --resume'
```

continue, resume 옵션은 클로드 실행 시 쓸 일이 빈번해서 위와 같이 ~/.zshrc 에다가 저장해뒀다. 참고로 그냥 c는 'clear' 명령어.

## 클로드 명령어

#### `Ctrl + S` 

입력한 프롬프트 stash. 클로드 코드가 스스로 작업하고 있을 때, 다음 지시를 미리 입력창에 타이핑해놓는 경우가 있는데 이 때 유용하다. 이미 길게 입력해둔 프롬프트는 두고 클로드에게 우선 지시하고 싶은 것이 있을 때 사용하니 익숙해졌다.

#### `Ctrl + R`

프롬프트 히스토리 검색. 

#### `/branch`

예전엔 `/clone` 명령어였던 것으로 추정. 여러 개의 수정 방안을 시도해보고 싶을 때 사용하기 좋다. 새로운 브랜치를 만들어두고 그 곳에서 작업을 하다가 그 방향이 아니면 기존에 브랜칭했던 단계에서 다시 작업하면 된다.

#### `/effort`

Speed vs Intelligence 트레이드오프를 조절하는 명령어. 높을수록 더 깊이 생각하지만 느려지고, 낮을수록 빠르지만 응답 품질이 낮아지는 방식.  
(레벨: low / medium / high / xhigh / max)

## 기타

- 음성 모드를 좀 더 자주쓰자. 옆에 사람이 있을 때는 잘 안 쓰게 되는데 익숙해지자.
- 코드 개발 시 테스트 및 lint 체크를 서브 에이전트로 분리했는데 왠지 토큰 소비가 더 많은 느낌.
- 내 개발환경 설정을 어딘가에 좀 백업을 해둬야 하나 어쩌나.
